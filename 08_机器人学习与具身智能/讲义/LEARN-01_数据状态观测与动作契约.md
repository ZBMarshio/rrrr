## 导读

**为什么学这一节。** 拿到一份示教或策略输出时，最先影响可用性的常是字段含义。state、observation与action必须和真实采样及执行接口对应。

**学完会有什么变化。** 从只按张量维度接模型，进到能追踪图像/状态属于哪个时刻、动作是绝对量还是增量，以及归一化在哪里发生。

**接下来能做什么。** 可以检查一个数据样本和一次动作执行，接通[LEARN-02](../导读.md#learn-02)的训练与滚动，也为VLA或其他策略的本体适配列出检查项。

## 先把一条经验读成一句话

在时刻 t 看见观测 o_t，策略提出动作 a_t，执行接口实际应用动作 u_t，随后得到下一观测 o_{t+1}。如果接 RL，再记录奖励和结束原因。模型输入、执行命令与物理反馈可能是三个不同的量。

state 是文件中的字段名时，先读它的定义。只有关节角的向量不一定构成动力学意义上的完整状态；同样的位置、不同的速度，下一步可能不同。observation 是策略实际能获得的信息，不能偷偷加入部署时不可得的真值。

先沿用第三阶段的低维示例：输入 [q1,q2,goal_x,goal_y]；q 用 rad，目标位置用基座平面的 m；动作是每步关节增量 rad。这里不是速度或力矩控制。

| 最低记录 | 为什么保留 |
|---|---|
| episode_id、step、采样时间 | 区分独立轨迹，追踪顺序和时延 |
| 观测字段、单位、坐标、可用时刻 | 知道模型到底看到了什么 |
| 策略原始输出、反归一化后的请求动作 | 定位网络与转换的边界 |
| 应用限幅/限位后的实际动作、下一状态 | 核对标签与执行结果 |
| 结束标志、原因、任务配置版本 | 解释成功、超时和无效样本 |

数据集可以分开保存元数据和逐步数组，不要求每行重复整份配置。真实机器人还要记录指令与反馈的差异；命令发出不能直接当作已运动。

## 两个容易被维度掩盖的错误

同为2维向量，[0.02,-0.01] 可能是关节增量，也可能是绝对角度。前者应加到当前 q，后者直接成为目标；shape 相同，结果可以完全不同。

限幅也会改变监督标签。教学后端设每步限幅 ±0.03 rad，第一关节上限1.00 rad。若当前 q1=0.99、请求 Δq1=0.06，先限成0.03，再限关节位置，实际只移动0.01。P3 默认用实际应用增量作标签，同时留原始请求供排查；训练和部署都使用同一套处理顺序。

学习器拟合的含义必须与执行器一致。输入/输出归一化统计只从 train 拟合，部署先反变换再执行；不能把归一化动作直接当 rad。

## 自己走一次数据链

先手写一条记录，再写读取/检查函数。用自己的话解释：观测由谁产生 → 哪个字段进模型 → 输出如何转换 → 哪个量真正应用 → 下一状态怎样验证。通过后再批量收集；不必先安装完整机器人学习框架。

无真机时，用 q_next=clip(q+clip(delta)) 的运动学后端检查契约即可。这个等式只验证教学接口，不证明电机跟踪或接触行为。

## 练习

<a id="ex1"></a>

### 第1题：请求和实际动作。约15分钟

q=[0.99,-0.30] rad，请求增量 [0.06,-0.02] rad，每维动作限幅 ±0.03，关节位置范围均为 [-1,1]。算下一状态与实际增量。若把请求当成实际标签，会教错什么？

<a id="ex2"></a>

### 第2题：字段名不等于语义。约20分钟

某数据的 state 仅含关节角，相机比关节采样晚50 ms，策略名义频率20 Hz。指出至少三个要补问的问题；这50 ms相当于几个名义决策间隔？

<a id="ex3"></a>

### 第3题：切样本前先划分。约20分钟

四个 episode 各100步。随机打散400步后切 train/val，和先划分 episode 再切相邻动作窗口，有什么不同？写出一份可追踪划分，不要求四条轨迹足够训练。

<a id="ex4"></a>

### 第4题：做一个小检查器。约45分钟

自己设计一条样本与元数据，检查至少8项契约；故意放入单位混用、重复step和非有限动作三个坏例子。保存错误信息和一条有效样本，先不写训练器。

## 直觉与复盘

数据契约像一张交接单：让下一位使用者知道每个数是在什么时候、什么坐标中、代表哪个动作。弄清这些，往往比换网络更早解决“能训练、不能用”。

复盘：把字段名遮住，你能靠元数据重新解释一条记录吗？
