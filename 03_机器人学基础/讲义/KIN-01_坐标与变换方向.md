## 固定一个贯穿本章的约定

点用列向量。R_A_B 的三列是 B 的三个单位坐标轴，用 A 坐标表示。p_A_B 是 B 原点在 A 中的位置：

```text
p_A = R_A_B @ p_B + p_A_B

T_A_B = [ R_A_B  p_A_B ]
        [ 0 0 0    1   ]

[p_A; 1] = T_A_B @ [p_B; 1]
```

“点在世界里没动，只换一种方式描述”和“把物体真的转动/平移”是不同操作，可能使用相同形式的矩阵。先写清正在做哪一种。

## 复合与逆，从一个点出发理解

```text
p_A = T_A_B @ T_B_C @ p_C
T_A_C = T_A_B @ T_B_C

T_B_A = inverse(T_A_B)
R_B_A = R_A_B.T
p_B_A = -R_A_B.T @ p_A_B
```

齐次点省略了补 1 的记号。右侧矩阵先作用；复合中的中间坐标必须对上。一般不能交换顺序，也不能把整个 T.T 当作 T 的逆。

位置点用末项 1，纯方向向量用末项 0；方向只旋转、不加原点平移。关节角列表也不是三维方向向量。

## 学习细节

- 每个变量至少记坐标、物理量、单位和形状。
- 图中的 parent→child 连接与数值映射方向要分别说清，用一个点检查。
- 同一名字 camera 在不同程序中可能代表机体坐标或 optical 坐标，查定义。
- 3×3 数组不一定是旋转矩阵；检查正交性与行列式。
- 数值乘法能执行，只说明形状兼容，不能证明物理意义正确。

## 练习

<a id="ex1"></a>

### 第 1 题：相机中的点，在基座中在哪里？约 20 分钟

B 原点在 A 中为 (1,0,0.5) m，B 相对 A 绕 z 正转 90°，点的 B 坐标为 (1,0,2) m。

画轴，写 R_A_B、T_A_B，算 p_A；再算回 p_B。先手算再用 NumPy，不必启动 ROS。

<a id="ex2"></a>

### 第 2 题：为什么平移不能总是交换？约 20 分钟

T_A_B 与第 1 题相同。C 相对 B 不旋转，原点沿 B 的 x 正向移动 0.2 m。

算 C 原点在 A 中的位置。再比较 T_A_B @ T_B_C 与反序乘法：反序虽能数值相乘，坐标标签是否还符合原来的链？

<a id="ex3"></a>

### 第 3 题：修复“整个矩阵转置就是逆”。约 20 分钟

写 rigid_inverse(T)，按刚体变换块公式求逆。验证 T_inv @ T≈I，点来回变换恢复，且对不含平移/含平移的例子都通过。

说明为什么只测一个纯旋转矩阵，可能漏掉错误写法。

<a id="ex4"></a>

### 第 4 题：把结果带回 TF，或复用已有证据。约 15 分钟

对应到 lookup_transform(target,source,stamp)，解释第 1 题要怎样查。记录 base/camera 的实际名称、方向与米单位。

第二章已做过时，引用旧结果并指出本节数学关系；没有运行环境时先保留数学验证，TF 收发另列待验证。

## 直觉与回顾

坐标像地址的参照方式。同一个点换了原点和轴，数值自然会变；这不意味着点本身移动了。旋转矩阵的列告诉你“新轴在旧地图上朝哪里”。

遇到混乱时，先画一个已知点和一根单位轴，往往比反复试矩阵顺序更快。写下你曾混淆的一个方向，并用具体点说明现在怎样检查。
