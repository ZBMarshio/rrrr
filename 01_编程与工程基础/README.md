## 本章导读

**为什么学这一章。** 实验室里的程序往往已经能运行，真正轮到你改它时，困难会变成：入口在哪，数据是谁改的，换个终端为何失效。这章帮助你逐渐接管一份程序的运行过程。

**学完会有什么变化。** 学习前，修改主要依靠模仿附近代码；学习后，你能沿输入、函数、对象、文件和环境解释一次运行，也能用小反例定位错误、保留一次有效修改。

**接下来能做什么。** 可以独立组织两关节轨迹分析工具，再把读写、验证、日志和排错能力带到ROS节点与模型训练。先完成一份CSV、一张有单位的图和一条复跑命令。

## 学习内容与掌握层次

| 层次 | 内容 |
|---|---|
| 必须掌握 | Python 模块、类、异常、配置与日志；NumPy 形状/广播/矩阵运算；C++ 引用、指针、const、类、STL、RAII 和智能指针；Linux、Git、基础 CMake、调试与基本测试。 |
| 了解即可 | 线程/进程、容器、基础复杂度分析、性能定位、依赖锁定与打包。 |
| 以后深入 | 高级 C++、并发、实时编程、CUDA、系统性性能优化。 |

## 前置与衔接

- 前置：已有 Python/Linux 基础先用练习检查；数学需求见公共基础目录。
- 去向：支持全部方向；C++ 先服务于 ROS 2 与机器人代码阅读，Python 先服务于数据和实验。
- 层次表示毕业前与研一的深度边界；先通过小练习检查，已掌握的部分跳过。

<a id="route"></a>

## 学习路线

本章的展开材料见[九节讲义导航](学习指南.md)。先用当前周需要的部分，不要求读完全部工程材料才进入 ROS 2。

1. 从读取关节数据、计算误差和画图开始，检查 Python、NumPy 和 Linux 的薄弱点。
2. 把脚本整理为可配置、可记录日志的程序，使用 Git 管理；同步阅读和修改一个小型 C++ 程序。
3. 结合 ROS 2 包学习 CMake 与调试；出现性能或部署问题时再补线程、容器等知识。

## 理论、代码与可验收成果

| 类型 | 当前要求 |
|---|---|
| 理论学习 | 理解数据类型、数组维度、作用域、对象生命周期和程序组织。 |
| 代码实践 | 实现轨迹数据读取、异常检查、速度估计与误差统计；用 C++ 重写其中一个小计算模块。 |
| 小项目/验收 | 一个有示例数据、运行命令、配置和结果图的轨迹分析工具。 |

无真机替代：使用合成或公开关节轨迹，全部可在本机完成。

成果尽量复用到总路线的项目版本中；运行成功、指标验证和硬件验证分别记录。
