## 你要逐步建立的能力

给你一份关节数据，你能说明每一列的含义，写程序读取和验证，算出可信的误差，留下别人能复跑的命令；程序出错时，你能沿着数据、路径、环境和调用关系找到证据。

本章共用一个练习背景：**两关节轨迹分析工具**。先做文件读写与曲线，随后补配置、异常处理、Git、C++ 小模块与调试。全部可以离线完成。

工程能力的一种直观表现是：隔了两周，你还能知道当时用了什么输入、为什么得到那个结果，以及下一步该从哪里接着做。

## 第一次打开时，先做这三件事

本工作区现为普通 Python 练习采用独立的 Conda 环境 `embodied-learn`。先按[环境使用说明](../学习环境使用说明.md)激活，再做下面的检查与练习。

1. 读 [ENG-06 的路径与解释器检查](讲义/ENG-06_Linux路径进程与环境.md#preflight)，写下当前目录和实际 Python 路径，约 10—15 分钟。
2. 做 [ENG-01 第 1 题](讲义/ENG-01_Python模块类与异常.md#ex1)：先写预测再运行，看看“两个变量”和“两个对象”在你脑中是否已经分清，约 15—25 分钟。
3. 开始 [ENG-02 第 1、2 题](讲义/ENG-02_NumPy形状广播与计算.md#ex1)，从下面的小数据算误差。今天只完成其中一题也可以，留下下一步。

如果对象题有困难，就回读 ENG-01 的小例子；如果预测全部正确，直接进入数组实践。不要把“看过一遍”当成过关，也不需要为了凑学习时间重复熟悉的内容。

## W01 怎么搭配这些材料

原周计划仍是“一份 CSV、一张有单位的曲线图、一条复跑命令”。可以按以下顺序分几次完成，不要求连续学完：

| 环节 | 选读与练习 | 大致投入 |
|---|---|---|
| 找准运行位置 | ENG-06 检查；ENG-09 解释器诊断 | 20—30 分钟 |
| 整理 Python 入口 | ENG-01 函数/模块/异常；第 3、4 题按缺口做 | 60—90 分钟 |
| 让计算可信 | ENG-02 第 1、2 题，观察每一维和计算方向 | 60—90 分钟 |

## 贯穿练习的数据约定

以下是人为构造的数值样例，**不是机器人实测数据**。你可以手工保存为练习项目中的 `data/trajectory.csv`：

```csv
t_s,q_ref_1_rad,q_ref_2_rad,q_obs_1_rad,q_obs_2_rad
0.0,0.0,1.0,0.1,0.8
0.1,0.1,0.9,0.0,1.1
0.2,0.2,0.8,0.4,0.6
0.3,0.3,0.7,0.1,0.9
```

| 数据 | 内存约定 | 物理意义 |
|---|---|---|
| `t` | `(N,)`，有限且严格递增 | 秒 |
| `q_ref`、`q_obs` | `(N, 2)`，浮点数且有限 | 两个固定顺序关节的弧度；每行对应一个时刻 |
| `error` | `q_obs - q_ref`，形状保持 `(N, 2)` | 有符号位置误差，弧度 |
| 每关节 RMSE | 沿时间维聚合，输出 `(2,)` | 各关节误差大小，弧度 |
| 差分速度 | `(N-1, 2)`，使用实际时间差 | 每个采样区间的平均变化率，弧度/秒 |

这份样例的每关节 RMSE 应约为 `[0.158113883, 0.2] rad`。这是自查基准；先写出计算过程再对照。数据随意改动后，不应继续期待同一数值。

建议练习项目结构如下，由你逐步创建，不要求现在全部实现：

```text
trajectory_lab/
  main.py
  trajectory.py
  config.json
  data/trajectory.csv
  runs/
  tests/
  README.md
```

将项目放在你自己的练习目录。讲义里的相对路径均相对明确的练习项目或配置文件解释；Git 的操作练习另用独立临时仓库。

## 每一节的实际学习动作

一次 45—90 分钟可以采用这个循环：

1. 先看本节目标与一题，写下输出预测或实现思路。
2. 只读资料表中解决当前问题的段落，通常先控制在 15—20 分钟。
3. 自己运行或实现，保留预期与实际的差别。卡住 15—20 分钟可先看提示。
4. 对照答案后关掉答案，改一个输入再做一次，解释变化。
5. 写 3—5 句复盘，并留下下一次第一步。

参考答案中的实现是一种写法；接口、结果与边界正确，你的实现可以不同。开放题给验收依据。整套轨迹分析工具由你组织，答案只提供局部示例与检查方法。

## 怎样判断“这一部分学会了”

四个信号可以逐步出现：能预测、能实现、能解释、换一个输入仍能验证。只跑通参考代码属于“已运行”；独立改动并解释后再记“已验收”。

想获得一些踏实感，可以记录非常具体的变化：“以前看到维度报错会乱加 reshape，现在先写每一维的含义”；“以前找不到文件就改绝对路径，现在先检查工作目录与配置基准”。这些变化比“我已经精通 NumPy”更容易确认。

每节最后的“直觉与回顾”是教学解释与建议，不是替你写好的个人感想。你的总结写进[练习与复盘记录](练习与复盘记录.md)，可以不同意讲义中的类比，只要能说明理由。
