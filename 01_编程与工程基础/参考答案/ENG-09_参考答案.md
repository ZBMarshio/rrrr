## 第 1 题

安装位置与运行解释器不一致。先确认运行入口的 sys.executable、该解释器的 pip 位置、该解释器的模块查找/导入结果。

题目中可以查询：

```bash
/opt/env_a/bin/python -m pip --version
/opt/env_a/bin/python -c 'import sys; print(sys.executable); print(sys.path)'
```

这些是题目中的假设路径，你的机器需换成实际存在的路径。确认需要此环境后，才决定在其中安装依赖或改用另一套已满足要求的解释器。

如果错误来自脚本首行、ROS console entry point 或 IDE，终端的 python3 路径可能仍不是实际运行入口，继续查对应启动方式。

## 第 3 题

新耗时为 `0.8 + 0.1/10 + 0.1 = 0.91 s`。加速比为 `1/0.91 ≈ 1.099`，并没有接近十倍。总耗时减少约 9%。

可以在读取、计算、绘图前后各取 perf_counter 差值，再测整体；先确认图形显示/文件写入是否包含在计时中。实际数据没有统一“应当几秒”的答案。

profile 的累计时间可包含子调用；不要把各函数 cumtime 直接全加起来当作总耗时。

## 第 4 题

每个 float64 占 8 字节，仅数据区：

| 形状 | 字节 | 十进制大小 | 二进制大小 |
|---|---:|---:|---:|
| (100000, 12) | 9,600,000 | 9.6 MB | 约 9.16 MiB |
| (100000, 100000) | 80,000,000,000 | 80 GB | 约 74.51 GiB |

还没有计入数组对象、其他数据与同时存在的中间结果。不要真的分配第二个数组来“确认会不会卡”。

普通 NumPy ndarray 通常使用主机内存并在 CPU 上计算，不因存在 NVIDIA GPU 自动改用显存。其他数组框架与互操作需按接口另行确认。

向量化能减少 Python 循环开销，但巨大广播结果仍可能让时间和内存同时变差。先看输入/中间/输出形状，再决定是否分块。
