## 第 1 题

两种启动分别尝试打开 `/tmp/demo/data/q.csv` 与 `/tmp/data/q.csv`。给脚本传绝对路径，不会自动把当前目录切换为脚本目录。

ENG-03 先解析配置文件位置，再以其 parent 作为数据相对路径的基准。前提是两次使用同一个配置文件；如果传入相对的 config 路径，它本身仍需要先解析。

自己的路径与版本输出没有统一标准答案，以实际检查为准。只写“Python 正常”不足以留作以后排错证据。

## 第 2 题

`&` 将 sleep 放后台；`$!` 是刚启动的后台任务的进程号；ps 查看这个 PID；kill 发送 TERM；wait 等待并取得该子进程的终止状态。

可在 wait 后立即用 `printf '%s\n' "$?"` 查看状态。Bash 中被 SIGTERM 终止时常见 143；不把该具体数值当成所有环境的通用输出。它与自然完成时常见的 0 不同。

Ctrl-C 通常作用于前台进程组；此题用准确 PID，便于区分“哪个进程收到了什么”。

## 第 3 题

在路径可穿越、脚本可读且解释器存在等前提下，bash hello.sh 由 bash 读取文件执行；没有 x 位也可工作。直接 ./hello.sh 要求执行权限，首行还指定解释器。

`chmod u+x` 给文件所有者增加执行权限，不代表给所有人开放读写。真实设备访问还涉及设备节点所属组、规则和驱动；应查具体设备，不用一条 chmod 覆盖所有问题。

文件系统挂载为 noexec 等情况也会影响直接执行。题目先在普通可写练习目录中观察基本机制。

## 第 4 题

A 后启动的子 shell 打印 `/tmp/data_example`。B 未设置时通常打印空行；A 的修改不会自动传播到 B。

可以在自己的 demo_setup.bash 写：

```bash
export ENG_LESSON_MARK="loaded"
```

在此前没有该变量的父 shell 中，运行 bash demo_setup.bash 后父 shell 仍没有它；source 后父 shell 得到 loaded。新开的子进程继承导出变量，子进程自己的修改不会自动写回父进程。

这能帮助理解 source ROS 环境，但尚未检查你实际 ROS 工作空间的加载顺序。
