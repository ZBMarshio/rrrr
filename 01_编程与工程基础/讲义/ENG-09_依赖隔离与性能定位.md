## 导读

**为什么学这一节。** 安装过包仍导入失败、启用GPU却没有变快，往往需要先检查正在用哪套环境、时间花在哪。本节让优化有明确对象。

**学完会有什么变化。** 从一出问题就重复安装或扩大硬件规模，进到能核对解释器和依赖来源，记录版本，并测量真正的耗时部分。

**接下来能做什么。** 可以维护独立学习环境，按[ML-09](../../07_机器学习与深度学习/讲义/ML-09_资源混合精度与微调.md#intro)测训练资源，也能在仿真与ROS工程中判断下一项优化是否值得做。

## 先解释“我明明已经安装过”

终端里找到的 python3 是一个程序，pip 也是一个命令入口，它们未必属于同一个解释器。先检查：

```bash
python3 -c 'import sys; print(sys.executable)'
python3 -m pip --version
python3 -c 'import numpy; print(numpy.__version__); print(numpy.__file__)'
```

`python3 -m pip` 明确让当前选中的 Python 运行它的 pip 模块。若报没有 pip，这也是定位信息，不意味着必须马上改全局环境。

激活 venv 主要影响当前 shell 的命令查找等设置；也可以直接用 `.venv/bin/python`。创建环境不会把已有系统包自动全部复制进去，环境目录通常也不作为可移植成品拷走。

## 需要新建纯 Python 练习环境时

先选一个确认可用的解释器，在自己的代码练习目录中：

```bash
python3 -m venv .venv
.venv/bin/python -m pip --version
```

需要 NumPy/Matplotlib 且网络和包源可用时，再在这套环境内安装它们。已有可用环境可继续使用；venv 创建失败时保留错误，先确认 venv 支持和解释器，不用改系统 Python 链接或对系统目录强行写包。

ROS 练习另外确认：预编译 rclpy 等与相应 Python 二进制版本兼容，纯 Python 环境能导入 numpy 并不能证明也能导入 ROS。按 ROS 实际工作空间的依赖方案处理，不把所有环境混成一套。

## 依赖记录应该包含什么

记录 Python/系统版本、直接依赖、实际安装版本、代码和数据版本、运行命令。`pip freeze` 是当前 Python 包的快照，通常包含间接依赖；它不是完整的系统、驱动和硬件复现证明。

学习阶段先做到别人能判断缺了什么。不为了“固定版本”升级一个已经能运行的实验环境。

## 性能判断的次序

先定义问题：数据多大、运行几次、是否包含读取和绘图、希望缩短哪段等待。再分别测：

- 整体耗时；
- 文件读取、计算、绘图各阶段；
- 主要函数的累计耗时。

用 `time.perf_counter()` 测实际经过时间；重复数次并明确预热、缓存和数据规模。`cProfile` 用来找调用与耗时分布，本身会引入开销；它不等于严格微基准。

对你的脚本可以从 `python3 -m cProfile -s cumulative main.py` 开始，有参数则按程序入口传入。优化后用相同输入对比结果与耗时，两者都要检查。

## 练习

<a id="ex1"></a>

### 第 1 题：安装给了谁？约 15 分钟

这是人为构造的诊断场景：

- 运行脚本的 sys.executable 是 `/opt/env_a/bin/python`；
- 直接执行 pip --version，输出位置属于 `/opt/env_b/`；
- env_a 导入 NumPy 失败，env_b 导入成功。

解释为什么“装过 NumPy”仍然失败。写出你下一步收集哪三项证据，如何针对确定的解释器查询 pip。再回到自己的终端做相同检查。

<a id="ex2"></a>

### 第 2 题：给别人一份可重建的说明。约 20 分钟

为轨迹分析工具写环境说明：Python、系统、直接依赖、实际版本、运行步骤与样例来源。区分手写的直接依赖清单与本环境包快照。

可在独立纯 Python 环境演示创建/使用流程；网络不可用时只做记录与诊断，明确没有完成重建验证。问自己：仅有 requirements.txt，哪些条件仍没有记录？

<a id="ex3"></a>

### 第 3 题：计算快十倍，整体会快十倍吗？后续约 20 分钟

假设总耗时 1 秒：读文件 0.8 秒、计算 0.1 秒、画图 0.1 秒。只将计算提速十倍，其余不变，新总耗时和整体加速比是多少？

随后用自己的程序分段测一次，不预设计算必定是瓶颈。若无法运行，就完成纸面分析，不编造计时结果。

<a id="ex4"></a>

### 第 4 题：省了循环，会不会吃掉更多内存？后续约 15 分钟

只计算内存，不实际分配大数组：

1. `(100000, 12)` 的 float64 数组仅数据区约多少字节？
2. 错误广播生成 `(100000, 100000)` 的 float64 中间结果呢？
3. NumPy 普通数组会因为电脑有 RTX 4060 自动放到显存吗？

解释为何“向量化”要同时看计算和中间数组大小。区分十进制 MB/GB 与二进制 MiB/GiB。

## 直觉与回顾

环境可以看成运行程序时实际使用的一套工具。你知道自己拥有某把工具，还需要知道这次拿起的是哪一套；解释器路径和模块位置提供的就是这个证据。

优化像压缩一段流程的等待：如果主要时间花在读文件，先把计算写得再花哨，也只改变了很小一部分。先量清楚，才知道下一小时投入哪里最有用。

请写一个现在能查证的判断，以及一个目前还没有测量的猜测。保留这一区别，是后续做训练实验与性能报告的基础。
