## 导读

**为什么学这一节。** 同一个脚本在不同终端表现不同，原因可能来自工作目录、解释器或继承的环境。运行位置本身就是程序输入的一部分。

**学完会有什么变化。** 从找不到文件就随意改路径，进到能核对命令解析、实际Python、文件基准和进程，解释环境怎样传给子进程。

**接下来能做什么。** 可以稳定启动自己的练习，排查[ROS-02](../../02_ROS2与机器人系统/讲义/ROS-02_包启动与参数.md#intro)的包与启动问题，并在[ENG-09](ENG-09_依赖隔离与性能定位.md#intro)中定位依赖所属环境。

## 本节怎样用

W01 先学路径与解释器检查；进程、权限和环境传播遇到问题再补。主要资料是作者课程 [Missing Semester：The Shell](https://missing.csail.mit.edu/2020/course-shell/)，选路径、命令、权限、输入输出与 shell 环境。具体命令选项可用本机 `man` 或 shell 的 `help` 查，不要求背完。

## 开始前的五项检查

在你实际准备运行练习的终端逐条执行：

```bash
pwd
command -v python3
python3 -c 'import sys; print(sys.executable); print(sys.version)'
python3 -c 'import numpy as np; print(np.__version__); print(np.__file__)'
git status --short
```

最后一条只有在 Git 仓库中才成功；若提示不在仓库，记录事实即可，不需要立刻在学习文档根目录初始化仓库。NumPy 导入失败时，保留错误，再按 ENG-09 检查解释器。

这五项分别回答：从哪里运行、找到哪个程序、它真正使用哪个 Python、库从哪里加载、当前代码有没有未提交修改。

## 命令怎样找到目标

1. shell 解析命令和参数，包括引号、变量与重定向。
2. 外部命令通常沿 PATH 查找；alias、函数和 shell 内建还会影响解析，可用 `type` 查看。
3. 新进程通常继承当前工作目录和导出的环境变量；程序再按自己的规则查找文件与库。
4. 程序退出后返回退出状态，终端不自动知道它是否达成了你的业务目标。

当前目录与脚本所在目录常常不同。Python 的 `Path("data/x.csv")` 默认按当前目录解释，不按脚本文件位置解释。

## 容易忽视的细节

- 路径包含空格时用引号，例 `cd "我的练习目录"`。变量作为单个路径参数时也通常写 `"$lesson_dir"`。
- `export` 让变量进入后续子进程的环境；已经打开的另一个独立终端不会被反向修改。
- `source setup.bash` 在当前 shell 中执行，常用于加载环境。`bash setup.bash` 开一个子 shell，里面的环境修改不会自动留在父 shell。
- `python3 script.py` 需要解释器能读取脚本；`./script.py` 还涉及文件执行权限与首行解释器声明。
- 文件的 r/w/x 与目录的 r/w/x 含义不同。目录 x 关系到路径穿越；排权限问题先看具体路径、所属用户与组。
- 进程号 PID、shell 的后台作业编号和 ROS 节点名是不同概念。先确认具体进程再发停止信号。
- `>` 通常覆盖目标文件，`>>` 追加；错误输出与标准输出是不同通道。做练习时先用新建的输出文件。
- 优先使用平台正常停止流程或针对自己进程的 TERM；强制终止不会替程序完成清理。

## 练习

<a id="ex1"></a>

### 第 1 题：脚本没动，文件为什么找不到？约 15 分钟

你有 `/tmp/demo/main.py` 和 `/tmp/demo/data/q.csv`，main.py 中写 `open("data/q.csv")`。

1. 在 `/tmp/demo` 下运行与在 `/tmp` 下运行 `python3 /tmp/demo/main.py`，分别尝试打开哪里？
2. 如果使用 ENG-03 的“相对配置目录”规则，哪一项约定消除了这个差别？
3. 跑一遍上面的检查，记录自己的实际路径。

<a id="ex2"></a>

### 第 2 题：只管理自己刚启动的进程。约 10 分钟

在单独练习终端中：

```bash
sleep 30 &
lesson_pid=$!
ps -p "$lesson_pid" -o pid,ppid,stat,comm
kill -TERM "$lesson_pid"
wait "$lesson_pid"
```

解释每行含义，观察 wait 的退出状态。若进程已经自然退出，记录这一时序并重新练习。不要把示例中的进程号替换为不认识的进程。

<a id="ex3"></a>

### 第 3 题：执行权限与读取权限。约 15 分钟

在自己的练习目录创建一个内容为 `#!/usr/bin/env bash` 和 `printf 'hello\n'` 的 hello.sh，保留可读但暂不给用户执行权限。

比较 `bash hello.sh` 和 `./hello.sh`。再使用 `chmod u+x hello.sh` 后比较，并解释改变的是哪个权限。对设备访问问题，为什么不能直接把这个做法当成通用答案？

<a id="ex4"></a>

### 第 4 题：环境向哪个方向传？约 15 分钟

终端 A 执行 `export ENG_LESSON_DATA="/tmp/data_example"`，然后启动 `bash -c 'printf "%s\n" "$ENG_LESSON_DATA"'`。另一个此前已打开且未设置该变量的终端 B 中执行同样的 printf。

预测两边输出。再解释运行 `bash setup.bash` 与 `source setup.bash` 的区别；这里只需用自己的小脚本演示设置练习变量，不操作实验室真实启动脚本。

## 直觉与回顾

可以把每个终端理解成有自己工作位置和工具摆放的一张桌子。启动子进程时，它接收一份环境；你在一张桌子上换了工具，不会自动重排另一张桌子。

排错时先问“我在哪、调用谁、用哪份数据”，往往能比反复重装更快缩小范围。写下一次“找不到”的具体证据：找不到命令、找不到 Python 模块、找不到数据文件，它们分别该查什么？
