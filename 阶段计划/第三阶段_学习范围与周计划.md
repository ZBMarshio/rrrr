| 成果 | 最低内容 | 验证边界 |

| P3-BC：状态行为克隆 | 示教数据→MLP策略→保存/加载→闭环滚动→与教师/简单基线比较 | 默认平面双关节运动学环境，不声称物理控制或真机操作 |

## 如何开始，哪些前置可以独立补

复用P1/P2的坐标、FK/IK、轨迹、日志和实验约定，不重新搭一套机器人系统。开始学习部分需要：

1. Python/NumPy、配置、日志和基本排错能独立使用。
2. 能解释状态/观测、指令/实际反馈、rad/m和时间；运动学任务可复用已验证FK/IK。
3. 训练基础若未提前学过，就在W22完成最低范围，不默认第一、第二阶段的PyTorch选做已经完成。
4. P2仍有缺口时，单独记录；BC可用低维运动学任务，RL可用标准环境先行。相机、MoveIt或真机接口的缺口不阻塞这两个入门成果。

只有把学习策略接回P2/真实平台时，才需要相应感知、执行、复位与任务判定接口都可用。不能直接把P2参考轨迹、VLA数据或公开视频默认为当前策略的兼容示教。

## W24 · 从离线误差走到BC闭环

时间：2027-04-19—2027-04-25。核心约8小时。

- 对应：[LEARN-02](../08_机器人学习与具身智能/知识索引.md#learn-02)、[LEARN-07](../08_机器人学习与具身智能/知识索引.md#learn-07)，复用ML-03/04/05/10。
- 理论：监督动作回归、示教覆盖、逐步滚动误差累积；离线loss与闭环成功率的区别。
- 代码：自己组织一个小MLP BC；先能拟合少量样本，再训练完整入门数据。只看val选模型，在独立reset后由策略逐步决定动作；保留教师与零动作基线。
- 成果：**BC学习曲线、离线动作误差、固定案例滚动表、失败轨迹与保存/加载演示**。

验收：滚动时的动作确由模型输出，评测过程中没有教师接管或使用目标真值动作；报告成功数/总数、最终位置误差及超时/限位/无效值。先跑一个训练seed、20个验证案例，最终测试集合继续留出。

替代：无真机/相机时沿用低维后端；低成功率也保留为有效失败分析，先查契约、教师与覆盖，不立刻同时换大模型和数据。

## W26 · 用成熟实现完成PPO训练与独立评测

时间：2027-05-03—2027-05-09。核心约8小时。

- 对应：[RL-03](../08_机器人学习与具身智能/知识索引.md#rl-03)、RL-04、LEARN-07。
- 理论：actor/critic、优势、PPO的新旧策略与裁剪直觉；数据由谁交互采集、几次更新、on-policy的含义。SAC先只了解其不同的数据/更新方式。
- 代码：默认SB3 PPO + CartPole-v1 + MlpPolicy。先短试跑记录交互步数与时间，再给一次预声明预算，例如总环境交互100000步；保存、重载，使用独立验证环境评测。记录实际步数，框架rollout可能使其略超过请求值。
- 成果：**随机基线、训练曲线、独立评测表、模型重载与方法数据流说明**。

验收：解释“采样→优势/目标→策略/价值更新→评测”；训练环境与验证环境分开，wrapper/奖励和归一化一致；报告回报、episode长度及terminated/truncated比例，不能仅截取最高训练曲线。

默认CPU起步：SB3说明PPO的MLP配置主要适合CPU，GPU不作为门槛。[PPO官方文档](https://stable-baselines3.readthedocs.io/en/master/modules/ppo.html) 无渲染训练，视频只录少量评测。初次用一个seed和20个验证episode，三seed重复留主线选择之后。

范围：使用成熟算法实现，自己的工作是配置、采样/评测/日志与解释；不将“调用PPO”写成“从零实现PPO”。当前预算是起点，不保证自动达到某个分数。

<a id="bc-task"></a>

## 默认BC任务的最小规格

这是复用P1的低维任务，先统一以下约定，再决定是否接MuJoCo或P2：

| 项 | 暂定配置 |
|---|---|
| 模型 | 平面双关节，L1=.3 m、L2=.2 m，FK与已验收P1一致；关节限位来自该教学模型配置 |
| 观测 | 当前q1/q2（rad）与目标TCP x/y（m），共4维；目标在基座平面坐标中 |
| 动作 | 本次关节增量Δq，2维rad，初始每维限幅±.03 rad；应用限幅/限位后存实际Δq |
| 时间 | 每次决策名义dt=.05 s；运动学后端按步更新q，不把墙钟快慢当真实控制性能 |
| 教师 | 复用已验证的局部IK/雅可比方法，决策只依赖当前观测；采样目标关节值仅用于生成可达目标，不作为隐藏的策略输入/标签捷径 |
| 结束 | TCP误差<.015 m持续5个决策步为成功；最多100步，无效数值/越界处理单列原因 |
| 数据 | 初始建议100个train、20个val、20个最终test案例，固定不同初态/目标ID；每个episode保存输入/动作/下一状态/结束原因 |
| 划分 | 独立案例集先冻结，训练预处理只拟合train；同一episode或其动作窗口不跨split |
| 基线 | 教师与零动作策略；相同案例、相同复位与结束规则 |
| 验证 | 教师先在开发/验证案例检查；失败不静默重采样消失。记录采集成功/尝试数，成功示教筛选及偏差也写明 |

初态/目标范围在W23根据P1教师可行性确定，并在策略训练前写入配置；初态本就满足成功条件的案例应单列，避免零动作基线因任务太容易虚高。测试集不因策略表现差而删改。

模型先用小MLP，不要求图像、语言或Transformer。归一化后的loss与物理rad/m指标分别报告；滚动时先反归一化，再应用相同动作约定。

如果已有统一的物理仿真接口可直接替换后端，但需重新验收真实反馈/控制周期、教师与任务指标，单独标记运动学与动力学结果。真实设备作为后续附加验证，不进入本期最低门槛。

<a id="rl-task"></a>

## 默认RL任务与评测约定

表格入门用FrozenLake-v1的固定4×4、关闭滑动，学习有限状态/动作与探索；深度RL用CartPole-v1/PPO，优先CPU/单环境起步。环境ID、版本、map/wrapper、奖励选项、time limit都保存。

CartPole默认奖励/结束说明以[官方文档](https://gymnasium.farama.org/environments/classic_control/cart_pole/)为准；本计划将“达到配置的500步上限且未因失衡/出界提前terminated”作为教学稳定保持率，同时报告真实episode回报和长度。这个自定义比例不是宣称达到某个通用机器人能力标准。

随机策略是最低基线；有可靠传统控制器时可附加，但不为本周单独开发复杂控制器。保存actor/critic模型后重载评测；如果使用观测/奖励归一化，统计量与wrapper设置一并保存。

训练seed、验证reset集合、最终test reset集合分开。初次验证20个episode足够看流程与失败；最终主线建议每个训练seed对固定20个test初态评测，报告分子/分母。默认确定性评测，随机策略的采样器也固定/记录；不以测试曲线挑checkpoint。

框架保存模型不自动承诺精确续训：RNG、环境状态、rollout/buffer、normalizer等有各自需求。入门只要求重载后可评测；若研究续训，再另设状态一致性实验。

## P3最低验收与深化验收

| 项目 | 最低保留证据 | 深化主线再补 |
|---|---|---|
| 训练工程 | 数据/环境/依赖版本、配置、运行入口、模型保存与重载预测 | 资源短测与所声明的恢复范围 |
