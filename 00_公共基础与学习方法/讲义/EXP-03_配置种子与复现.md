# EXP-03：把实验从记忆里搬到文件里

## 导读

**为什么学这一节。** 上次运行成功，今天却重现不了，常常是输入、环境或随机状态只留在记忆中。记录这些条件才能继续查原因。

**学完会有什么变化。** 从只记一个seed，进到能分别保存配置、实际数据、版本和随机状态，并检查重跑时究竟哪项发生了变化。

**接下来能做什么。** 可以留下可复查的实验入口，为[ENG-03](../../01_编程与工程基础/讲义/ENG-03_文件配置日志与结果.md#intro)的工程记录和[ML-03](../../07_机器学习与深度学习/讲义/ML-03_数据训练验证与恢复.md#intro)的训练恢复提供完整上下文。

## 资料与范围

查 [NumPy 1.26 随机生成器](https://numpy.org/doc/1.26/reference/random/generator.html)，深度学习时再用 [PyTorch 2.6 Reproducibility](https://docs.pytorch.org/docs/2.6/notes/randomness.html)。工程文件组织复用第一章；完整 PyTorch/CUDA checkpoint 复用第七章 ML-03，不在这里重写训练框架。

## 一个 seed 不是全部条件

固定 seed 有助于固定某个生成器的序列，不会自动固定软件版本、数据文件、调用顺序、仿真参数、设备或所有随机源。保存实际采样值与数据版本，比只写一个整数更容易核对。

建议最小配置包含：问题/模型、单位、数据/场景版本、划分、种子、关键参数、成功条件、解释器/依赖、运行入口与输出位置。代码、数据和配置分别有版本；同一配置摘要不代表读到的是同一份数据。

配置摘要检查“是否同一份规范内容”，不证明配置合理，也不替代配置本身。数据文件可另算内容 hash；写明 hash 对应字节文件，不是模糊的目录名字。

恢复随机序列要保存生成器状态。若先取了随机数又临时多取一次，后面的输入会变化；调试打印如果调用 sample，也在改变实验。

## 练习

<a id="ex1"></a>

### 第1题：最小配置。约20分钟

给本章测量校正实验写配置：数据文件/划分、米制单位、方法、拟合规则、指标、seed来源、解释器版本与输出位置。区分已知生成参数和估计参数，避免拟合时偷用真值。

<a id="ex2"></a>

### 第2题：键顺序与数据变化。约20分钟

写规范 JSON 摘要：键顺序变化不改摘要，参数变化应改变；拒绝 NaN。对数据文件做 SHA-256，再改一个字节，观察摘要。为什么 hash 本身不能判断实验是否正确？

<a id="ex3"></a>

### 第3题：同 seed 但不同调用顺序。约20分钟

同一 seed 的两个局部 RNG，一个先抽一次再抽3个，另一个直接抽3个。比较结果。再从相同实际输入重跑拟合，区分“随机输入不同”与“求解器不同”。

<a id="ex4"></a>

### 第4题：保存随机状态。约25分钟

使用 PCG64，抽3个数后保存 state，继续抽5个；重建生成器并恢复 state，确认接下来的5个一致。把 state 写入 JSON 后再恢复一次，记录版本。这个例子为什么还不能替代神经网络训练 checkpoint？

## 直觉与回顾

复现记录是给下一次工作的接口。写清输入与状态，下一次就能继续判断问题，而不是重新猜测上次发生了什么。
