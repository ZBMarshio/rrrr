# SIM-07：每次实验从哪里开始，决定比较是否公平

[学习指南](../学习指南.md) · [知识索引](../知识索引.md#sim-07) · [提示与答案](../参考答案/SIM-07_参考答案.md)

<a id="intro"></a>

## 导读

**为什么学这一节。** 第二次实验继承了速度、积分或旧队列时，比较就已经换了起点。完整复位让改动之间的差异有机会被公平解释。

**学完会有什么变化。** 从只把关节放回零位，进到能列出模型、控制器、缓存和随机源的状态，按固定ID恢复并保存失败。

**接下来能做什么。** 可以做重复控制实验，建立[SIM-08](SIM-08_Gymnasium与环境接口.md#intro)的reset，并为[LEARN-07](../../08_机器人学习与具身智能/导读.md#learn-07)组织固定初态下的策略评测。

## 资料与范围

查 [MuJoCo 状态与复位](https://mujoco.readthedocs.io/en/3.17.0/programming/simulation.html)、[Gymnasium reset](https://gymnasium.farama.org/api/env/)，复用第一章记录与公共实验方法。

## 复位不只把 q 放回去

检查 qpos/qvel、时间、执行器状态与输入、求解器状态，以及你的积分器、动作/延迟队列、目标、缓存和步数。mj_resetData 负责相应 data 初始化，不负责 Python 控制器或外部设备。

它也不会把你改过的 model 质量、阻尼和其他参数恢复为原文件值。做参数对照时，可每个案例从明确基线重新编译模型，再应用该案例配置。

## 种子是条件之一

固定随机数生成器与版本，保存真正采样到的初态/参数，不只保存 seed。模型、求解器、依赖版本、控制周期与运行后端也要固定；跨平台/并行运行不默认逐位一致。

Gymnasium 的环境随机数与 action_space 的采样器有各自种子。固定手工动作序列时直接保存序列；不要以为 env.reset(seed=...) 自动固定所有其他随机来源。

## 试验集合先冻结

先列全部 trial_id、初态、目标与条件，再运行；调参集合和最终评测集合分开。中断后根据已保存 ID 继续，不只重跑成功案例。

成功标准包括误差、速度/任务条件与保持窗口，提前写明。失败保留在总次数里；没有有效误差测量的样本单独计数，不能悄悄滤掉。

## 练习

<a id="ex1"></a>

### 第 1 题：完整复位检查。约 25 分钟

先施加输入使单关节运动，再复位并重跑。分别演示遗漏 qvel、控制器积分或旧队列会造成什么。改一个 model 参数后 resetData，它会恢复吗？

<a id="ex2"></a>

### 第 2 题：生成并保存案例集。约 20 分钟

用局部 RNG 生成 10 个单关节初态/目标，给稳定 ID。相同种子是否复现同组数据？记录实际数组/配置，再将其中一组作为独立评测。

<a id="ex3"></a>

### 第 3 题：给配置一个可核对的摘要。约 20 分钟

将模型/场景版本、步长、增益、执行器语义等组成 JSON 配置，规范序列化后算摘要。键顺序变化和实际参数变化分别应怎样影响摘要？

<a id="ex4"></a>

### 第 4 题：总次数不能随结果变化。约 25 分钟

四个预定案例中，两成功、一控制超时、一输入被拒绝，其中被拒绝案例无位置误差。计算成功率与有效误差样本数，保存各失败原因。

如果只拿有误差数据的三次作成功率分母，会怎样？重复 trial_id 应如何处理？

## 直觉与回顾

复位让比较从同一条起跑线开始；案例 ID 让中断和失败也有位置。这样一次没跑成的实验仍能为下一次提供明确线索。

复盘从新进程恢复一个指定案例，指出哪些条件来自文件，哪些仍藏在内存里。
