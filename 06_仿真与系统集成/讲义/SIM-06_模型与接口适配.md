# SIM-06：适配层要把含义接对

[学习指南](../学习指南.md) · [知识索引](../知识索引.md#sim-06) · [提示与答案](../参考答案/SIM-06_参考答案.md)

<a id="intro"></a>

## 导读

**为什么学这一节。** 两个模块都输出相同长度数组，也可能交换了关节、单位、零位或动作类型。适配层负责把各自正确的模块接成同一个含义。

**学完会有什么变化。** 从让消息格式能够通过，进到能检查名称映射、正方向、位置偏置、坐标和时间，用往返测试验证转换。

**接下来能做什么。** 可以先用文件或固定样本接通P1/P2，再为[LEARN-01](../../08_机器人学习与具身智能/导读.md#learn-01)的训练数据和[VLA-01](../../08_机器人学习与具身智能/导读.md#vla-01)的动作输出核对平台兼容性。

## 资料与范围

复用 [ROS-08](../../02_ROS2与机器人系统/讲义/ROS-08_ros2_control与执行接口.md)、[CTRL-03](../../04_机器人控制与运动规划/讲义/CTRL-03_控制接口与执行链.md)和第五章的坐标/时间契约。本节写最小数据适配，不要求新建通用实时桥接。

## 同长度数组也可能接错

关节名集合、排列、单位、正方向、零位、绝对/增量和执行器语义逐项明确。qpos 索引按模型查，不能从 joint ID 或字符串猜含义。

位置、速度、力矩的映射不同。位置零位偏置不会原样加到速度；力矩映射还涉及传动和功率一致性。示例中的符号/偏置函数只用于位置。

URDF 的 link/joint 与 MJCF 的嵌套 body/joint 表达不同；支持导入不表示惯量、碰撞、坐标和执行器已对齐。导入后逐项核对，ROS 插件与 MuJoCo actuator 的配置也分别说明。

## 一个位置映射例子

明确约定 `q_device=s*q_model+b`，s 为逐关节 ±1，b 的单位为 rad。反向映射为 `q_model=s*(q_device-b)`；设备原始若用度，先按声明换成 rad。

位置、速度、控制值分别记录，不靠函数“猜单位”。关节限位也要变换到同一坐标后核对。

## 坐标和四元数也要适配

MuJoCo 使用 wxyz 四元数顺序；常见 ROS 消息是 xyzw。改顺序不等于改变参考坐标系，不能用分量重排代替 T_A_B。

P2 使用 `T_base_target=T_base_camera T_camera_target`，再乘目标到工具接近位姿。相机/标定版本、frame、时间及工具定义属于同一数据链。

## 先离线接通

为每条中间记录保存 schema、模型/标定/场景版本、名称、单位、采样时间和状态。先固定一条记录进入下游检查，再接动态生产者。

约定谁拥有物理推进循环，谁只读状态，谁写参考；在线化时再补缓冲、时钟与生命周期。消息通了之后仍需检查实际数值与完成条件。

## 练习

<a id="ex1"></a>

### 第 1 题：按名字重排。约 20 分钟

来源 names=[joint_2,joint_1]、values=[0.2,-0.4] rad；目标顺序 [joint_1,joint_2]。实现并检查缺失、重复和额外名字。

<a id="ex2"></a>

### 第 2 题：符号与零位往返。约 20 分钟

q_model=[0.2,-0.4]、s=[-1,1]、b=[0.1,-0.2] rad。求 q_device，再反算。速度能否也加 b？设备原始是度时在哪一步转换？

<a id="ex3"></a>

### 第 3 题：四元数只换顺序。约 20 分钟

把 ROS 的绕 z 轴 90°四元数转换为 MuJoCo 顺序，核对表示的旋转。零四元数和明显非单位输入应怎样处理？

<a id="ex4"></a>

### 第 4 题：P1/P2 的最小离线契约。周项目内完成

选一条已有轨迹或目标记录，标明 schema、名字、单位、坐标、时间与版本，送入下游验证。故意改一项名字或标定版本，看是否在进入执行前被识别。

## 直觉与回顾

适配层像翻译：先保证“谁、什么量、哪个方向、何时”一致，再改变表示。只让两个数组形状相同，无法完成翻译。

复盘追踪一个具体数字从上游到实际作用，逐项写它在哪里换了名字、单位、坐标或物理含义。
