# SIM-02：ctrl 是执行器输入，不自动等于关节角

[学习指南](../学习指南.md) · [知识索引](../知识索引.md#sim-02) · [提示与答案](../参考答案/SIM-02_参考答案.md)

<a id="intro"></a>

## 导读

**为什么学这一节。** 同样叫ctrl的数组，可能代表力矩、位置参考或别的执行器输入。把含义与索引接对，控制实验才有可解释的对象。

**学完会有什么变化。** 从按关节编号填数，进到能按名字查qpos/DOF/执行器地址，说明传动、限幅与实际广义力的关系。

**接下来能做什么。** 可以把已有控制器接到明确执行器，核对[CTRL-03](../../04_机器人控制与运动规划/讲义/CTRL-03_控制接口与执行链.md#intro)的接口假设，也能为学习策略定义正确动作。

## 资料与衔接

读 [MuJoCo XML 执行器](https://mujoco.readthedocs.io/en/3.17.0/XMLreference.html)中的 motor、position、gear、ctrlrange/forcerange；与 [CTRL-03](../../04_机器人控制与运动规划/讲义/CTRL-03_控制接口与执行链.md)一起核对单位与控制层。

## 名字、编号和数组地址分开

joint ID、qpos 地址、qvel/DOF 地址、actuator ID 是不同索引。hinge 常各占一个数，但 freejoint 为 7 个 qpos（位置+四元数）和 6 个 qvel；球关节也有不同维度。

按名称访问或查 jnt_qposadr/jnt_dofadr，不能把 joint ID 当所有数组的下标。一个关节可以有不同传动/执行器结构，nu 不保证等于关节数。

## motor 与 position 的区别

本章单转子是直接关节 motor、gear=1：ctrl 在该约定下提供力矩作用；data.qfrc_actuator 是映射到广义坐标的执行器力。gear 改变传动映射，要重新解释力和长度/速度关系。

position 执行器是内置伺服结构。在直接 gear=1 的例子中，ctrl 是位置参考，力来自参考偏差与配置增益；它仍通过动力学演化 q，不是直接赋值 qpos。

ctrlrange 约束控制输入，forcerange 约束执行器输出力，两者不同。内部限幅不保证 data.ctrl 数组会被改写成限幅值；检查实际作用时看执行器/广义力。

## 练习

<a id="ex1"></a>

### 第 1 题：列出索引表。约 20 分钟

在 2R 中按名称找关节位置地址、速度地址和 actuator ID；再读球落地模型的 nq/nv/nu。为什么不能写“所有关节都是 qpos[joint_id]”？

<a id="ex2"></a>

### 第 2 题：输入、限幅与实际作用。约 25 分钟

单转子分别输入 0.2 和 10，forward 后比较 ctrl、actuator_force、qfrc_actuator；核对限制。只把 gear 从 1 改成 2，在同一小输入下比较广义力。

<a id="ex3"></a>

### 第 3 题：同样 0.3，不同物理含义。约 30 分钟

在独立模型副本中，把 motor 改成 position，显式 kp=8、kv=0.8、gear=1，位置参考限幅 ±1.5 rad，输出力限幅 ±2 N·m。

比较 motor 的常力矩 0.3 与 position 的常参考 0.3，记录两者参数。它们不是同单位动作，不能据此比较控制算法优劣。

<a id="ex4"></a>

### 第 4 题：给控制链写契约。约 20 分钟

从 PID/策略输出→ctrl→执行器→广义力→qpos/qvel 逐项写名称、单位、频率、限制。复用第四章 PID 时应该使用哪一种后端？位置参考后端还需要哪一层控制？

## 直觉与回顾

一个数组的长度和数值看起来很熟悉，也可能连接完全不同的物理端口。先确定执行器怎样解释输入，再判断动作有没有合理结果。

复盘找一段“数值没错但单位错了”的调用，用执行器配置和实际作用日志说明原因。
