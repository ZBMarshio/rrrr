# CTRL-09：命令发出前后，都有需要核对的条件

[学习指南](../学习指南.md) · [知识索引](../知识索引.md#ctrl-09) · [提示与答案](../参考答案/CTRL-09_参考答案.md)

## 导读

**为什么学这一节。** 参考值合法，也可能因速度、延迟或当前状态而难以执行。命令前后的约束检查决定任务何时继续、何时退出。

**学完会有什么变化。** 从只给位置做裁剪，进到能区分参考限制与实际状态限制，检查超时、容差和停止到了哪一层。

**接下来能做什么。** 可以为离线或模拟执行设计可检查的拒绝/退出规则，结合[ROS-10](../../02_ROS2与机器人系统/讲义/ROS-10_排错状态与停止条件.md#intro)记录失败，为策略接入准备执行边界。

## 资料与本期范围

复用第二章 [ROS-06 时钟与新鲜度](../../02_ROS2与机器人系统/讲义/ROS-06_时间戳同步与时钟.md)、[ROS-10 排错与停止](../../02_ROS2与机器人系统/讲义/ROS-10_排错状态与停止条件.md)，不重写相同命令门控。

## 约束不仅是位置上下界

至少区分状态限制与参考/输入限制。参考位置合法时，速度/加速度可能过大；力矩饱和时，实际跟踪也会偏离参考；当前实际状态还决定有没有足够空间减速。

一个理想估算：

`d_stop=|v| delay + v²/(2 a_brake)`。

前提是延迟内速度恒定，之后保证有恒定净减速度 a_brake，忽略其他动态。若实际条件不满足，就不能把结果当实际停车保证。

## 参考限速不等于状态限速

位置参考每次最多改变 vmax·dt，是限制参考序列的一种方法。这里使用上次发送的参考，不是把实际位置直接替换成参考；它也没自动限制加速度、实际速度、碰撞和跟踪误差。

dt 的来源要明确。时钟倒退、陈旧状态、错误形状/单位应在门控阶段拒绝；“等反馈恢复”是状态，不能继续默默发送旧轨迹。

## 停止到了哪一层

停止生成新目标、取消上层 action、底层控制器改变输出、驱动执行停机、机构实际停住，各自需要证据。仅有取消响应，不足以说明机构已经停止。

位置保持、零速度、零力矩有不同物理意义；存在重力时，零力矩通常不能代替位置保持。沿用平台明确提供的停止/恢复接口和操作规则。

每次新实验明确初始状态、积分状态、延迟队列、旧目标与时间基准怎样处理。恢复后是否自动继续原目标，要作为明确行为设计和验证。

## 练习

<a id="ex1"></a>

### 第 1 题：有多少减速空间？约 15 分钟

v=0.8 rad/s、delay=0.05 s、a_brake=2 rad/s²，求理想停止距离。距位置上界只有 0.15 rad 是否足够？哪些假设一变，估算就需重做？

<a id="ex2"></a>

### 第 2 题：只限制参考变化。约 25 分钟

上次参考 [0,0]，新目标 [0.3,-0.4] rad，dt=0.02 s，vmax=[1,0.5] rad/s。生成一次受限参考。

写局部函数并拒绝无效输入。解释它为什么不保证实际关节速度和加速度都满足要求。

<a id="ex3"></a>

### 第 3 题：复用门控，验证一次中断。约 25 分钟

沿用第二章 command_gate/is_fresh，构造：正常反馈→反馈超时→新目标到来→反馈恢复。给每一步写可发送/拒绝原因与控制状态。

明确失联时上次命令在底层如何处理；若没有接口证据就记为未确认，不能仅因 Python 不再发布而宣称已经停住。

<a id="ex4"></a>

### 第 4 题：计划结束与实际结束。约 20 分钟

轨迹计划 1 s 完成，但到 1 s 时误差仍有 0.1 rad，实际速度仍非零。分别判断“计时到终点”“控制器成功”“任务到达”是否已有充分证据。

为数值/mock 实验列出超时、容差、取消、实际停止的记录字段，复用本章日志；不需要新增真机测试。

## 直觉与回顾

控制链条像一串交接，每层说“完成”都有自己的含义。最终用户关心的通常是实际任务结果，而你需要用中间证据定位差距。
