## 第 2 题

加权为 2/5 和 3/5。仅当每样本等权、固定输出大小、两批都按均值定义损失时如此。

```python
import torch

def accumulated_step(model, batches, loss_fn, optimizer):
    batches = list(batches)  # 这里只收集一次更新的小型微批列表。
    if not batches or any(len(x) == 0 or len(x) != len(y) for x, y in batches):
        raise ValueError("nonempty paired microbatches required")
    total = sum(len(x) for x, _ in batches)
    optimizer.zero_grad(set_to_none=True)
    value = 0.
    for x, y in batches:
        loss = loss_fn(model(x), y)
        if loss.ndim != 0 or not torch.isfinite(loss):
            raise ValueError("finite scalar mean loss required")
        fraction = len(x) / total
        (loss * fraction).backward()
        value += loss.detach().item() * fraction
    optimizer.step()
    return value
```

model 模式和设备由调用者设置。普通 Linear、无随机操作时可对照完整 batch 到数值精度；Dropout、BatchNorm、不同归一化分母可能不等价。变长序列改用有效 token/元素数加权，并处理全无效微批。

## 第 3 题

以下为 PyTorch 2.6 的 CUDA FP16 流程参考。本章 GPU 重核实际执行了此函数，并在含 Dropout 的 MLP 中验证 AMP 续训，见[恢复记录](../示例核对记录.md#gpu-resume)。scaler 在外层创建一次 `torch.amp.GradScaler("cuda")`，checkpoint 时保存其状态。这里一次调用更新一次，没有合并梯度累积。

```python
def cuda_amp_step(model, x, y, optimizer, scaler, max_norm=1.0):
    if not torch.cuda.is_available() or x.device.type != "cuda" or y.device != x.device:
        raise RuntimeError("available CUDA and CUDA inputs required")
    if max_norm <= 0:
        raise ValueError("positive clipping threshold required")
    model.train()
    optimizer.zero_grad(set_to_none=True)
    with torch.autocast(device_type="cuda", dtype=torch.float16):
        pred = model(x)
        if pred.shape != y.shape:
            raise ValueError("matching regression targets required")
        loss = torch.nn.functional.mse_loss(pred, y)
    if not torch.isfinite(loss):
        raise ValueError("nonfinite loss")
    scaler.scale(loss).backward()
    scaler.unscale_(optimizer)
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)
    scaler.step(optimizer)
    scaler.update()
    return loss.detach().item()
```

GPU 测量在预热后同步，清峰值统计，再运行确定数量步骤，记录 `max_memory_allocated`、`max_memory_reserved` 与每步时间；两项内存含义不同。吞吐应注明样本/秒或 token/秒。AMP 不保证更快或总是稳定，结果以当前模型实测为准。

上面的 helper 每次会检查 loss 并返回 item，包含同步，适合先学会流程。资源测量使用相同的前向/反向/裁剪/更新顺序，但把有限值检查与 item 移到计时窗口外，预热后每 40 步同步一次；不能把两种实现的时间混成同一指标。本章的[短测结果](../示例核对记录.md#gpu-resources)注明测量条件，不代表该 helper 每次调用的耗时。

scaler 可能检测到非有限梯度而跳过 optimizer 更新，因此应区分训练调用次数与实际更新次数；仅观察 loss 有限不等于所有梯度都有限。基础正确性先检查参数/梯度和 scaler 状态，再做性能测量。

本次遗漏 scaler 的对照中，最终权重仍一致，但 scale=1024，与完整恢复的 8192 不同。不要把“权重没变”解释为 scaler 无需保存；验证应包含状态本身，也不要断言漏 scaler 必然让当前权重不同。
