# ML-01：每一个维度都要有含义

## 导读

**为什么学这一节。** 模型处理的是张量，而你的任务关心样本、时间、关节和像素。先让每个维度都有含义，才能判断计算是否在做预期的事。

**学完会有什么变化。** 从靠reshape消除报错，进到能追踪shape、dtype、device和广播，识别形状合法却样本配对错误的计算。

**接下来能做什么。** 可以准备FK回归或图像输入，进入[ML-03](ML-03_数据训练验证与恢复.md#intro)的训练，也能读[LEARN-01](../../08_机器人学习与具身智能/导读.md#learn-01)中的状态与动作张量。

## 资料与范围

读 [PyTorch Tensors](https://docs.pytorch.org/tutorials/beginner/basics/tensorqs_tutorial.html) 的创建、属性、操作与 NumPy 互转。先掌握 shape/dtype/device、索引、广播、矩阵乘法、reshape/permute；稀疏张量和底层存储以后再学。

## 怎么学

先在纸上写：一批 64 个双关节输入 `q:[64,2]`，预测和标签都是 `[64,2]`，单位分别为 rad 和 m。`B` 是 batch，`D` 是特征维，图像另用 `[B,C,H,W]`，序列可用 `[B,T,A]`。形状相同仍需核对列顺序、坐标和单位。

再用 NumPy 写一遍矩阵运算，换成 Tensor。`@` 按矩阵规则运算，`*` 是逐元素；`mean(dim=0)` 消去样本维；`keepdim=True` 帮助表达按列标准化。先预测结果形状，再运行。

`reshape` 重新解释元素排列，`permute` 调整轴；把 NHWC 变成 NCHW 应调整轴，不能靠 reshape 凑形状。非连续内存、共享存储先用小数组观察，暂不背所有细节。

输入、参数、标签要在兼容设备与精度上。回归常用 float32；类别标签用于 CrossEntropy 时用 long。设备迁移返回新张量，`x.to(device)` 的结果要接住。`from_numpy` 可能共享 CPU 内存，需要独立日志时 copy/clone。

本机 GPU 路线先完成三个证据：is_available 为 True、一次计算输出位于 cuda:0、一次 backward 后参数的 grad 也位于该设备。`.to("cuda")` 是把数据搬到 GPU，和改变数值类型/切断计算图不是同一件事。GPU Tensor 转 NumPy 做图通常用 `tensor.detach().cpu().numpy()`，只在日志/评测边界这样做。

## 练习

<a id="ex1"></a>

### 第 1 题：维度说明。约 20 分钟

写出主项目中一批输入、线性权重、偏置、输出、按样本位置误差的形状。用 3 个样本运行一次，说明 `x @ W.T + b` 中每一步。

<a id="ex2"></a>

### 第 2 题：抓住广播错误。约 20 分钟

预测 `[[1],[2],[3]]`、标签 `[1,2,3]`，都表示三个标量。直接相减是什么形状？为什么 MSE 非零？写 `checked_mse`，遇到形状不一致就拒绝，并测试空输入、NaN 和正常二维输入。

<a id="ex3"></a>

### 第 3 题：轴变换。约 20 分钟

用元素各不相同的 `[2,3,4,1]` NHWC 数据变成 NCHW。比较 permute 与 reshape 的元素位置，解释为什么单通道时不容易暴露错误；再把 C 改为 2 验证。

<a id="ex4"></a>

### 第 4 题：设备与共享内存。约 20 分钟

打印解释器、torch 版本、CPU 张量的 shape/dtype/device，再查 GPU。用 NumPy 数组和 `from_numpy` 证明共享修改，再用 clone 隔离。把输入和 Linear 模型放到同一 GPU，运行前向/backward，检查输出/参数/grad.device；故意漏搬标签，记录报错。没有 GPU 时用 CPU 完成并记明未测项。

## 直觉与回顾

张量的形状相当于数据的接口说明。计算能执行，只说明数学运算被允许；每一行是否对应同一个样本，还需要你自己负责。

复盘：从一个形状正确、语义错误的例子出发，说出除了 shape 还要检查哪三项。
