## 导读

**为什么学这一节。** 模型结构只是实验的一部分，数据顺序、验证和保存状态决定能否持续训练与复查。一个完整小循环比孤立调用更接近真实工作。

**学完会有什么变化。** 从照着脚本按运行，进到能组织Dataset与batch，说明谁更新参数、谁选择模型，并区分恢复预测与接着训练。

**接下来能做什么。** 可以完成自己的FK训练工程，再把同样入口用于[LEARN-02](../../08_机器人学习与具身智能/导读.md#learn-02)；需要时按[ML-09](ML-09_资源混合精度与微调.md#intro)接GPU、AMP与资源记录。

## 资料与范围

按顺序选读官方 [Datasets & DataLoaders](https://docs.pytorch.org/tutorials/beginner/basics/data_tutorial.html)、[Optimizing](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)、[Saving and Loading](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html)。前两篇抓数据流和一轮更新，保存篇区分推理权重与续训状态。先用 CPU 看懂单步，再迁移到单 GPU；两者均使用 num_workers=0，不急着上训练框架。

## 学习步骤

1. 用解析 FK 生成有单位的数据，train/val/test 分开。只用 train 拟合输入均值/尺度，再将同一变换用于其余集合。
2. Dataset 表达一个样本，DataLoader 组成 batch 并控制洗牌。每批显式得到输入、标签；保留配置、种子和样本身份。
3. 训练时 train→清梯度→前向→损失→反向→step；验证时 eval+no_grad，不更新参数。
4. 每个 epoch 后保存日志；只依据 val 选 best。测试集合不参与选择，方案冻结后评测。
5. 新进程重建相同结构并加载权重，验证预测。续训再恢复优化器、轮次和随机状态。

迁移 GPU 时，先确定 device，将模型移到该设备，再创建 optimizer；本章的 run_epoch 接收 device，将每批输入和标签搬到相同位置。Dataset/洗牌 generator 仍放 CPU，不要求把整个数据集预先塞进显存。输入标准化的统计量也要与运算所在设备匹配。

先验证一个 batch 的输出、loss、参数和 grad 所在设备，再长跑。GPU 不会修复广播、标签配对或动作单位错误；先完成 CPU 小样本检查仍有价值。

`batch` 是一组样本，`epoch` 是遍历一轮训练数据，`step` 在这里指一次优化器更新。512 样本、batch64、200 epoch 是 1600 更新；梯度累积时更新次数另算。最后一个 batch 常不足整批，统计损失应按真实样本数加权。

train 的批损失来自不断变化的模型。要与 val 公平画曲线，在 epoch 结束后固定当前模型，分别以 eval 重新计算 train/val；或者清楚标注两种曲线定义。

## 保存与恢复的边界

推理至少要结构、权重、预处理和输出解释。续训还需要 optimizer、next_epoch、调度器/AMP（如果用了）、数据顺序和随机状态；继续选模还要保留历史 best_val 与日志。CPU RNG、CUDA RNG、DataLoader generator 分别有状态。

答案保留 CPU 入门片段，并增加单 GPU 与 AMP 的状态片段。本次核对单进程、num_workers=0、epoch 边界，在新 Python 进程中恢复 CUDA FP32/AMP；不承诺 batch 中途、多 worker、多 GPU 或跨版本逐位一致。确定性设置见 [PyTorch 2.6 文档](https://docs.pytorch.org/docs/2.6/notes/randomness.html)，本次运行条件见核对记录。

`best_state=model.state_dict()` 得到的内容可能继续引用变化的参数存储；保留最佳快照用 deepcopy 或当场保存。自建 checkpoint 用 Tensor 与基本类型，读取用 `weights_only=True`；不要把加载任意来源对象作为必要学习步骤。

## 练习

<a id="ex1"></a>

### 第 1 题：数据与标准化。约 30 分钟

实现主项目数据生成，核对 q=[0,0] 时末端 [0.5,0]。相同局部 seed 重复生成一致。只在 train 算均值/标准差，说明为什么 val 不应单独标准化。

<a id="ex2"></a>

### 第 2 题：一个可解释的 epoch。约 40 分钟

自己写 train/val 循环，先用简单 Linear。用 5 样本、batch=3 检查损失加权，确认验证前后权重完全不变，并拒绝空 loader 和非有限 loss。

<a id="ex3"></a>

### 第 3 题：保存后换进程。约 30 分钟

保存权重、结构配置与输入统计。用新模型加载，检查固定输入预测一致。演示 state_dict 引用与 deepcopy 的区别。不要仅检查“文件存在”。

<a id="ex4"></a>

### 第 4 题：真正接着训练。约 45 分钟

一个含 Dropout 的小 MLP，用 Adam 和洗牌 loader，比较连续 6 epoch 与 3 epoch 后保存、在新进程恢复再训练 3 epoch。先做 CPU，再选单 GPU。分别遗漏 optimizer、DataLoader RNG、CPU/CUDA RNG，观察哪个随机来源影响当前计算。

AMP 续训还要恢复 scaler；同时核对其状态与参数，而非只看一轮 loss。CPU RNG 不负责 GPU 上 Dropout 的取样，不能只把原来的 CPU 代码加 .cuda() 就认为恢复完整。

第二阶段约 3 小时的选学只要求一次小训练与预测恢复；完整状态接续实验可留第三阶段。

## 直觉与回顾
