# ML-09：先估算，再用小实验测量

## 导读

**为什么学这一节。** 显存不够或训练慢时，先知道哪些张量与操作在占资源，才能选择有效改动。精度与微调方式的收益需要具体测量。

**学完会有什么变化。** 从依赖参数量或GPU利用率猜资源，进到能估算、预热、同步和记录峰值，解释微批累积与scaler的作用。

**接下来能做什么。** 可以为自己的视觉/序列实验做短试跑，决定batch、精度或冻结策略，并给后续方法选择提供资源依据。

## 资料与范围

查 [PyTorch 2.6 AMP](https://docs.pytorch.org/docs/2.6/amp.html)、[AMP examples](https://docs.pytorch.org/docs/2.6/notes/amp_examples.html)、[CUDA memory](https://docs.pytorch.org/docs/2.6/notes/cuda.html#cuda-memory-management)。LoRA 只读[原论文](https://arxiv.org/abs/2106.09685)低秩更新的结构与参数数量。

优先掌握 batch/序列长度/分辨率/参数更新范围的资源影响。混合精度、LoRA、激活重算以后随任务做；分布式训练不进入本阶段主线。

## 哪些东西占内存

FP32 可训练参数每个 4 B，梯度约 4 B，Adam 两个矩状态约 8 B，合计约 16N B；这是特定假设下的持久张量预算，不含激活、临时结果、缓存、实现额外副本。冻结参数仍需存储本身及必要中间特征，不能把“可训练参数少”视为“总显存同样少”。

朴素注意力的 score 张量为 [B,H,T,T]，序列长度翻倍时该项约四倍；高效内核可能不显式保存完整矩阵，不能拿朴素公式预测实测峰值。

先用最小 batch 前向/反向，再记录实际峰值与吞吐。测 GPU 时间应预热并同步；记录精度、分辨率、序列长度、batch、模型版本，不能比较条件不同的两个数字。没有 GPU 时做 CPU 正确性和预算核对。

本次以 TinyCNN、batch64、1×16×16 输入测 CPU FP32 / CUDA FP32 / CUDA FP16 AMP：每种在独立进程中预热 10 步，随后测 3 组×40 步。数据预先放到目标设备，计时不含读盘/数据搬运；包含前向、损失、反向、裁剪、优化器及 AMP 状态更新。数值与边界见[资源记录](../示例核对记录.md#gpu-resources)，不要把短测结果当成所有模型的速度比例。

## 有限资源下的选择

减 batch、分辨率或序列长度会改变计算/统计条件；梯度累积可增加一次更新所见样本，但不自动等同 BatchNorm/Dropout 下的大 batch。FP16 AMP 通常用 autocast+GradScaler；unscale 后再裁剪，scaler 在训练循环外创建并保留状态。

LoRA 将某些权重更新写成 ΔW=BA，低秩只限制这部分更新，不保证任务效果，也不删除基础模型。视觉输入预处理、训练数据和闭环验证依然要做。

## 练习

<a id="ex1"></a>

### 第 1 题：算清字节。约 20 分钟

1000 万个可训练参数，按上述 FP32+Adam 假设估算持久张量 MiB。再算 [B=2,H=4,T=128] FP32 attention scores；T=256 后多少？这些数为什么不能直接等于总峰值显存？

<a id="ex2"></a>

### 第 2 题：不等长微批。约 30 分钟

5 个样本拆成 2+3，两批均值损失应怎样缩放再 backward？用 float64 线性模型对照完整 batch 的梯度与一次 SGD 更新。不要简单每批除以 2。

<a id="ex3"></a>

### 第 3 题：资源测量与 AMP。约 30 分钟，有 GPU 时做

先记录实际可用 GPU/内存，再按相同输入比较 FP32/AMP 的损失有限性、峰值与时间。检查裁剪与 scaler 顺序，写明容差与版本。只在测量窗口前后同步，避免每步 item/打印把同步开销混入算法吞吐；同时明确训练循环是否包含这些开销。

将 max_memory_allocated 与 max_memory_reserved 分开记录，前者是 Tensor 分配的峰值，后者含 PyTorch allocator 保留内存；两者都不是 nvidia-smi 中所有进程占用之和。无 GPU 时只读流程、完成估算，状态保留未测，不据 CPU 结果声称 GPU 加速。

<a id="ex4"></a>

### 第 4 题：LoRA 更新范围。约 20 分钟

512×512 权重，秩 r=8，A/B 新增多少参数，占原矩阵多少？列出冻结基础权重、训练 A/B、只训练任务头三种方案的差异。选哪一种应由什么实验判断？

## 直觉与回顾

资源限制把问题变得具体：哪些信息值得保留，哪些参数真的需要更新。先用小实验验证训练目标，往往比先寻找最大模型更容易看清下一步。

复盘：当显存不足时，你改的设置是否同时改变了任务信息或优化条件？
