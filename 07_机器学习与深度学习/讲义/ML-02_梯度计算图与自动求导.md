# ML-02：让一次参数更新可以手算

## 导读

**为什么学这一节。** loss下降之前，先要知道一个参数为何被更新。把一次梯度手算出来，是理解整套自动求导流程的最小抓手。

**学完会有什么变化。** 从把backward与训练看成一个动作，进到能区分前向图、梯度、清零与step，定位断图和模式切换问题。

**接下来能做什么。** 可以独立核对一个小训练，为[ML-03](ML-03_数据训练验证与恢复.md#intro)排错，也为后续BC、策略梯度与动力学网络理解更新来源。

## 资料与范围

读 [Automatic Differentiation](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)，卡在导数时补 [MML](https://mml-book.github.io/) 第 5 章向量微积分中导数、链式法则。当前只要求一阶梯度，Hessian、自动微分实现以后深入。

## 从数据流到梯度流

固定 `x=[1,2]`、`y=[1,3]`，模型 `y_hat=w*x+b`，损失是两个样本的均方：

$$L=\tfrac12\sum_{i=1}^2(wx_i+b-y_i)^2.$$

这里的 1/2 来自样本均值，不是额外再乘一次。先手算 w=b=0 时的 loss、两个偏导，再用 autograd 核对。SGD 更新 `w←w−η∂L/∂w`；梯度指向局部上升方向，减去它才是下降尝试。学习率过大仍可能上升。

前向计算建立图；backward 沿依赖传播梯度；optimizer 持有参数并更新。`backward()` 不会自动替你 step。默认梯度累积，所以每次独立更新前清零。

`detach` 切断关联，`item` 变成 Python 数值，重新 `torch.tensor(old_tensor)` 不会重接原图。做日志可以 detach/item，作为训练损失的必经路径则会断梯度。不要靠随手加 requires_grad 来修补。

`model.eval()` 改 Dropout/BatchNorm 等层的行为；`torch.no_grad()` 控制是否记录求导图，两者职责不同。普通推理常同时使用。

## 练习

<a id="ex1"></a>

### 第 1 题：手算再更新。约 25 分钟

求上例初始 loss、∂L/∂w、∂L/∂b。学习率 0.1 更新一轮，算新 loss。写出每个值单位随量纲如何变化，不需要给所有深度网络量命名。

<a id="ex2"></a>

### 第 2 题：有限差分。约 25 分钟

用 float64 和中心差分 `[L(w+h)-L(w-h)]/(2h)` 检查 autograd，h=1e-6。再对同一参数重新前向/backward 两次，不清零，观察梯度；不要用“已释放的旧图”混淆这个实验。

<a id="ex3"></a>

### 第 3 题：找断图点。约 20 分钟

分别尝试将预测 detach、将 loss.item() 当 loss、把预测重新构造成 Tensor。解释原参数的梯度为何不存在或 backward 报错。然后只在日志路径 detach，确认更新仍发生。

<a id="ex4"></a>

### 第 4 题：两个开关。约 20 分钟

用含 Dropout 的小层分别组合 train/eval 和有/无梯度记录。记录输出随机性与 `requires_grad`，解释为什么 eval 不等于冻结参数。

## 直觉与回顾

反向传播是一次“哪些参数对这个误差负责”的计算。它忠实计算你写出的目标；目标、样本配对或量纲写错了，梯度仍可能非常正常。

复盘：如果 loss 不变，你会先证明“梯度算出”和“参数真的更新”中的哪一件？
