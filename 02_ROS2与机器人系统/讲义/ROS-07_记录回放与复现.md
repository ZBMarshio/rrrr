## 导读

**为什么学这一节。** 设备时间不稳定时，一份记录可以让同一个问题反复出现。学会录包和回放，会把排错从等待现场变成可重复分析。

**学完会有什么变化。** 从只保存一段视频，进到能说明录了哪些消息、时间和元数据，知道复现的是输入、显示还是执行过程。

**接下来能做什么。** 可以离线重跑节点、检查TF与状态，配合[EXP-03](../../00_公共基础与学习方法/讲义/EXP-03_配置种子与复现.md#intro)保存代码配置，为感知或学习数据问题留下现场。

## W02 目标与资料

原始合成发布者退出后，用录包重新向记录节点提供状态。W04 加上模型与 TF，第二阶段加上图像与标定信息。

## 先明确 bag 保存了哪一层

bag 保存选定话题的消息与相关元数据；回放重新发布这些消息。它没有自动保存你的源码、所有参数、设备内部状态和整个运行环境。

回放状态话题可重现模型显示输入，不能因此证明真实机器人再次执行了同样动作。执行/命令话题另有风险与语义，本章初期只录自己的合成状态。

消息 header.stamp 和 bag 存储时间戳是两个字段。前者由发布者约定，后者由录制/写入方式决定并用于回放调度，不能假设它们完全相等。

## 一次 W02 录包流程

在自己的练习目录、相同练习 domain 中，先启动记录：

```bash
mkdir -p bags
ros2 bag record -s sqlite3 -o bags/w02_states --topics /learn_ch2/joint_states
```

输出目录要是新的运行名。另一个终端启动合成发布者，确认录制端订阅与数据流，运行几秒后正常 Ctrl-C 停止录制，等待其结束，再查看：

```bash
ros2 bag info bags/w02_states
```

关闭原发布者，保留或重新启动自己的记录节点，再回放：

```bash
ros2 bag play bags/w02_states
```

记录前先确认话题，结束后检查实际消息数和起止时间。只看到 bag 目录，不能说明录到了有效数据；四条短序列可能在发现前结束。

## 模型阶段要多考虑三件事

1. **状态来源：** 原始发布者和 player 不要无意同时向同一状态话题发布。
2. **TF 来源：** 可录 TF 并回放，或回放 JointState 让模型节点重新计算；重复发布同一坐标边会混淆来源。
3. **时间来源：** 要按历史采集时刻查动态 TF，就统一相关节点的模拟时间与 /clock，或做明确时间映射。

固定模型可重新提供静态边；录制 /tf_static 时还要检查迟加入历史与 QoS。带相机时记录图像、CameraInfo、必要 TF，并另存模型/标定/配置版本。

## 细节

- 开始时显式列话题，避免一次录下整个系统的大图像或无关内容。
- 正常结束让缓存与 metadata 完成写入，备份前确认文件可读。
- play --rate 改回放调度速度，不自动改消息里的 header.stamp。
- play --clock 发布 /clock；使用它的节点仍要设 use_sim_time=true。
- 循环回放可能使模拟时间回到起点。差分、同步队列和 episode 状态应正确分段/清理。
- QoS override 解决特定端点需要，先查实际配置，不能把它当成所有丢帧的统一修复。
- 原始 bag 保留，分析产生的 CSV、图和统计另存，并说明过滤/重采样规则。

## 练习

<a id="ex1"></a>

### 第 1 题：录到的到底是什么？约 25 分钟

按上述流程录自己的合成状态，写下实际话题、类型、存储插件、消息数、起止时间与输入来源。人为选择一个不存在的话题，观察等待或无数据时的证据，再正常结束。

不要求消息数恰好等于标称频率乘时间；解释差异可能来自哪些环节。

<a id="ex2"></a>

### 第 2 题：源节点退出后仍能观察到输入。约 25 分钟

关闭原发布者，回放 bag。让记录器保存到另一份 CSV，比较关节名、位置与消息时间字段。

验收：能指出 player 是新的消息发布者；在只分析状态字段时，重放内容与保存消息一致；消息接收时间则属于这次回放。丢失或截断要如实计数。

<a id="ex3"></a>

### 第 3 题：模型抖动或 TF 报错，先查哪一项？后续约 25 分钟

场景 A：bag player 与原 state_source 同时存在；场景 B：录了 /tf，回放时也运行 robot_state_publisher；场景 C：历史图像按 stamp 查 TF，却有节点仍用墙钟。

逐项写出来源、时间或配置冲突，选择一条一致的复现方案。不要一边修改所有设置一边期待故障消失。

<a id="ex4"></a>

### 第 4 题：两倍速回放改变了什么？约 20 分钟

同一 bag 中两条消息采样 stamp 相差 0.1 秒，理想情况下两倍速回放，它们在墙钟中的发布间隔约多少？header 间隔会变吗？

设计一个复现清单，包括源码、参数、URDF/标定、时钟、话题与评测输入。若无法运行回放，可先完成字段比较和纸面分析，运行证据另列。

## 直觉与回顾

bag 更像保存了经过某些窗口的单据，回放让这些单据再次流过窗口。它有助于把现场问题带回桌面，但窗口之外的信息还需要你主动保存。

复盘时写清“这次我复现了哪一层”。当你能把状态、模型、时间和执行分开说明，录包才会成为可靠的实验工具。
