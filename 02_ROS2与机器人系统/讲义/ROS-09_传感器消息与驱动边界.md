## 导读

**为什么学这一节。** 一张图或一串深度数到达算法前，已经经历采样、解码和消息封装。字节布局、单位或标定关系出错，会一路影响后续结果。

**学完会有什么变化。** 从能订阅就直接reshape，进到会检查encoding、step、frame、时间与CameraInfo，识别无效值和驱动边界。

**接下来能做什么。** 可以验证相机/深度消息，给[VIS-01](../../05_机器人感知与视觉/讲义/VIS-01_图像像素与OpenCV.md#intro)和[VIS-05](../../05_机器人感知与视觉/讲义/VIS-05_深度RGBD与点云.md#intro)提供含义明确的输入，也更容易定位感知偏差来自哪里。

## 一条传感数据链

`设备采样 → 总线/SDK → 驱动解码与标定/单位处理 → ROS 消息 → 下游算法`。

驱动要交付的不只是一串数字，还包括它们的量纲、坐标、采样时刻与有效状态。算法输出错了，也可能是前面这些约定发生了变化。

## 图像消息里值得逐个检查的字段

| 字段 | 含义与检查 |
|---|---|
| height/width | 行数与像素列数，区别于数组通道 |
| encoding | 通道顺序、位深等，如 rgb8/bgr8/16UC1 |
| step | 一整行占的字节数，可能包含填充 |
| data | 总字节区，通常应与 step×height 对应 |
| is_bigendian | 多字节元素需注意端序，不能只看 dtype 名 |
| header | 采集时刻与光学坐标，和相关 CameraInfo 对齐 |

两列 RGB8 每行有效像素是 6 字节，但 step 可以为 8。直接把全部字节 reshape 为 (height,width,3) 可能失败或错位。

CameraInfo 的 Python 字段 k 是 9 个数的行优先矩阵；内参对应的分辨率、裁剪、图像是否去畸变都要匹配。没有标定的零内参不能当成可用模型。

## 深度与总线的细节

- encoding 描述存储形式，不足以替代完整设备单位约定。某设备明确定义毫米时再换成米，并说明无效值规则。
- 图像颜色顺序错误可能仍“能显示”，但算法输入已经变了。
- 设备时间与主机时间需要对应，不能把到包时间直接称为采样时间。
- 串口/TCP 的一次 read 不一定刚好返回完整协议帧；还可能有多帧、半帧和前导噪声。
- 按厂商协议处理帧头、长度、校验、端序、符号位、缩放和状态码，再做单位转换。
- 协议校验成功还需数值范围、校准与状态有效性检查。具体驱动的超时/重连作为后续专题。

## 练习

<a id="ex1"></a>

### 第 1 题：有行填充的 2×2 RGB 图。约 25 分钟

合成 Image：height=2、width=2、encoding="rgb8"、step=8、data 如下：

```python
data = bytes([
    255, 0, 0, 0, 255, 0, 0, 0,
    0, 0, 255, 255, 255, 255, 0, 0,
])
```

先画出四个像素颜色，再实现只处理 rgb8 的解码函数，返回独立的 (2,2,3) uint8 数组。验证错长度、step 太小与不支持的 encoding 被拒绝。

<a id="ex2"></a>

### 第 2 题：CameraInfo 对的是哪张图？约 20 分钟

标定分辨率是 640×480，图像现在缩小为 320×240，算法仍直接用原 k。说明哪里不一致；若纯等比例缩放且没有裁剪，fx/fy/cx/cy 应怎样变化？

再说明如果已经去畸变、裁剪或使用校正图，为什么不能只套这个缩放规则。

<a id="ex3"></a>

### 第 3 题：这份设备说明中的深度。约 15 分钟

假设设备明确声明 16 位无符号深度单位为毫米，0 表示无效。原值 [1000,0,2000] 应如何解释为米？你会把无效值记成 0 米吗？

再列出把这个深度像素交给空间定位前要核对的图像对齐、内参与时间条件。

<a id="ex4"></a>

### 第 4 题：分段字节流中的关节角。后续约 30 分钟

这是教学协议，真实设备用自己的协议：

```text
AA 55 | angle_low angle_high | checksum
共 5 字节；角度为 little-endian signed int16，单位 0.01 度
checksum = 前 4 个字节之和 & 0xFF
```

输入分四次到达：

```python
chunks = [
    b"\x00\xAA",
    b"\x55\xE8",
    b"\x03\xEA\xAA\x55",
    b"\x18\xFC\x13",
]
```

实现缓存、寻找帧头、等待完整帧、校验、解码和转 rad。期望得到两个有效角度；再加入一个坏 checksum，确认它不生成有效读数。

## 直觉与回顾

驱动像把设备语言翻译成系统语言。翻译除了数字，还要保留“什么量、哪个方向、什么时候、是否可信”。

一张图看起来正常，不代表字节布局和算法约定全都正确。复盘时选一个字段，说明少检查它会产生怎样的、可能不立刻报错的后果。
