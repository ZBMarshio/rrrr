## 本章导读

**为什么学这一章。** 机器人系统通常由许多程序一起工作。看到节点启动、话题有数据，只是观察到了几个局部现象；这一章让你理解消息、模型、时间、控制接口怎样接成一次完整任务。

**学完会有什么变化。** 学习前，容易把系统故障概括为ROS没连上；学习后，你能指出谁产生数据、谁处理、在哪个时刻属于哪个坐标系，以及命令经过哪些组件才形成反馈。

**接下来能做什么。** 可以写最小发布/订阅与记录节点，核对模型和TF，沿控制链排查问题。这些能力将支持视觉定位、仿真联调和学习策略接入。

## 学习内容与掌握层次

| 层次 | 内容 |
|---|---|
| 必须掌握 | 节点、话题、服务、动作、参数、QoS 基础；包/launch/colcon；URDF/Xacro、TF2；传感器消息、时间戳、仿真时间；rosbag2；ros2_control 状态和命令接口。 |
| 了解即可 | DDS、Executor、回调组、生命周期节点、CAN/串口等设备通信。 |
| 以后深入 | 实时执行、多机同步、复杂驱动和系统级性能优化。 |

## 前置与衔接

- 前置：01 的程序组织、Linux 与构建基础；TF2 与 03 的坐标变换并行学习。
- 去向：为 04 控制、05 感知、06 集成、08 策略部署提供通信、时间和硬件接口。
- 层次表示毕业前与研一的深度边界；先通过小练习检查，已掌握的部分跳过。

<a id="route"></a>

## 学习路线

各节具体资料范围、易错细节、练习与直觉解释见[十节讲义导航](学习指南.md)。章节顺序用于检索，实际执行跟随当前周任务。

1. 从最小节点与 launch 入手，明确通信类型与消息字段，完成一条记录和回放链路。
2. 引入机器人模型和 TF2，检查关节名称、单位、坐标系和时间；同时学习对应的运动学概念。
3. 接入 mock hardware 或现有驱动，追踪命令到控制器再到状态反馈的过程。

## 理论、代码与可验收成果

| 类型 | 当前要求 |
|---|---|
| 理论学习 | 理解通信语义、坐标系、时间和状态/命令的区别。 |
| 代码实践 | 实现状态发布、动作请求、参数配置和数据记录；阅读一条已有硬件接口调用链。 |
| 小项目/验收 | 可启动、可记录和回放的小系统，以及启动图、数据流图和一次排错记录。 |

无真机替代：使用合成消息、rosbag2、RViz 和 mock hardware；动力学另外在 MuJoCo 中验证。

成果尽量复用到总路线的项目版本中；运行成功、指标验证和硬件验证分别记录。
